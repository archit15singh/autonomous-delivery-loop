# ALB header matching in Argo Rollouts

| What readers can verify | Previous guide | Candidate guide |
| --- | --- | --- |
| Supported matcher | Router support listed, with no ALB-specific match type | `headerValue.exact` |
| Canary readiness | No ALB header example | `setWeight: 20` creates available canary replicas before the preview rule |
| Route behavior | Described in general traffic management docs | Matching requests go to the canary at weight 100. The final step removes the preview rule. |

Both exact revisions passed MkDocs. Only the candidate contains the ALB-specific section. The hosted replay extracted its YAML, applied it to a Kubernetes 1.37 fixture, and ran the exact Argo Rollouts controller. The Ingress gained an `X-Preview: true` condition, a 100-weight action for `canary-service:80`, and the preview path. After promotion past the pause, the controller removed the path and both annotations. Four ALB reconciler tests and the existing exact-match validation test passed.

The replay checks the Kubernetes configuration that Argo Rollouts produces. It uses no AWS controller or ALB data plane.
